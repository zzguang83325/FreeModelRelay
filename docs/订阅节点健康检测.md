# 订阅节点健康检测与生命周期

> 2026-10-20 任务交付文档。覆盖：定时自动检测、失效自动删除、上游 IP 封禁永久标记、订阅只增不删、文件持久化与重启加载、后台「全部检测 / 单独检测」。

## 1. 背景与需求

zen（opencode.ai）出口依赖机场订阅节点的多出口轮询，但存在三类痛点：

1. **节点失联无感知**：动态订阅每次拉取轮换服务器 IP，旧节点会悄悄失效，zen 请求撞上坏节点只能靠重试硬扛；
2. **上游按出口 IP 封禁**：429 长等待 / 403 `FreeTierError`（"abusive traffic from this IP address"）意味着该出口已被上游拉黑，继续轮询只会浪费重试；
3. **订阅刷新全量替换**：旧实现每轮刷新整表替换，导致节点端口漂移、健康状态丢失。

目标：节点定时体检、坏了自动标记移除、被封永久拉黑、订阅刷新只增不删、全部状态落盘可恢复。

## 2. 总体设计

```
机场订阅 URL (zzguang / liangxin, 动态订阅)
   │  定时刷新(默认 30 分钟): fetch(v2rayNG UA) → 解析分享链接 → mergeSubNodes 只增不删
   ▼
sing-box Box (每订阅一个实例, 每节点一个本地 socks inbound, 11200 起端口池)
   │
   ├──► zen 代理池轮询出口 (剔除 dead/banned)
   │
   └──► 健康检测 (默认 5 分钟一轮, 启动 2 分钟后首次)
         经节点 socks 出口对 opencode.ai:443 做 TCP+TLS 握手
         (与 zen 实际上游一致, 不发 HTTP、不消耗配额)
         │
         ├─ 成功 → ok (清零失败计数, 记录延迟)
         ├─ 连续 2 次失败 → dead → 从节点表删除 + 重建 Box
         └─ zen 请求命中封禁信号 → banned → 永久移出(仅手动清除)

全部状态持久化: data/.subscriptions.json (config/nodes/ports/status/health)
重启: startSavedBoxes 直接用文件节点起 Box → 3s 后异步刷新订阅 → 2min 后探测循环
```

## 3. 核心机制

### 3.1 节点探测（[subscription.go](../internal/app/subscription.go)）

- **探测方式**：`probeSubNode` 经 `socks5://127.0.0.1:<localPort>` 拨号到 `opencode.ai:443`，完成 TLS 握手（SNI=opencode.ai）即判定可用——全链路验证到上游 TLS 层，能排除节点侧 SNI 劫持，且零配额消耗。
- **常量**：`subProbeTarget=opencode.ai:443`、`subProbeTimeout=12s`、`subProbeWorkers=12`（并发 worker）、`subDeadThreshold=2`（连续失败阈值）。
- **全量探测** `probeSubNodes(trigger)`：跳过 banned 节点 → 12 并发探测 → 结果统一写回 Health 表 → 持久化；返回 `probeSummary{total/ok/dead/banned/newDead/recovered/durationMs}`。`subProbing` 原子标记防止全量/定时/手动并发重入。

### 3.2 失效删除

连续 2 次探测失败（`fails >= subDeadThreshold`）→ `removeDeadNodes`：从 Nodes/Ports/Health 三表删除 → 同步 subLives → `rebuildSubBox(urlKey)` 重建受影响订阅的 Box → 刷新视图并持久化。

删除只由健康检测驱动；若节点仍在订阅内容里，下一轮刷新会作为新节点自动加回（端口重新分配）。

### 3.3 上游 IP 封禁（永久标记）

判定信号（[zen.go](../internal/app/zen.go) `isIPBanResponse` + 429 分支）：

- 429 且 `Retry-After` 解析值 **> 1 小时**；
- 403 响应体含 `FreeTierError` / `abusive traffic`（上游明确指向当前出口 IP，换节点即可恢复）。

命中 → `subBanNodeByURL(url, reason)`：按请求实际使用的代理 URL 反查节点并标记 `banned`（记录 `bannedAt`/`banReason`），清除该 URL 冷却，持久化。封禁节点：

- 探测轮次直接跳过（不再浪费时间）；
- 不再进入 zen 轮询池；
- 后台「♻️ 清除封禁」按钮（`/admin/api/subscriptions/unban`）手动批量解除。

配套：`isRateLimited` 关键词补入 `freetiererror`、`abusive traffic`，保证 403 封禁也能触发退避重试 + 换节点。

### 3.4 冷却按代理 URL 记账（[proxy_pool.go](../internal/app/proxy_pool.go) 重构）

节点随刷新/检测/删除频繁进出代理池，**数组索引会错位**，旧实现按索引冷却会把冷却记到别的节点头上。重构后：

- `zenProxyPick{idx, url}` 携带 URL，`zenProxyCooldowns map[string]time.Time` 按 URL 记账；
- `cooldownZenProxy` / `clearZenProxyCooldown` / `zenProxyAvailable` / `zenProxyCooldownStatus` 全部以 URL 为键；
- zen 网络错误路径也冷却实际拨号出口 10 分钟，避免重试连撞同一坏节点。

### 3.5 订阅只增不删（mergeSubNodes）

- **只增不删**：刷新时新节点加入，已有节点保留（端口稳定复用、健康状态延续）；删除仅由 3.2 的健康检测驱动。
- **节点身份 Key = sha1(协议|节点名)**（[parseShareURI](../internal/app/subscription.go)）：zzguang/liangxin 都是动态订阅，每次拉取轮换服务器地址（CF 优选 IP），按内容哈希做 Key 会导致同一逻辑节点每轮被当成新节点、无限膨胀。改名后同名异 Key 视为同一逻辑节点：沿用旧端口、更新节点定义、删旧 Key；同名去重 sweep 兜底收敛。
- 无名节点回退内容哈希；刷新尾部清理无对应节点的 Ports/Health 残留记录。

### 3.6 持久化与重启加载

- 落盘文件：`data/.subscriptions.json`（已被 `.gitignore` 的 `/data/` 规则覆盖，不入库），包含 `config`（订阅 URL/间隔）、`nodes`（节点完整定义，按 urlKey 分组）、`ports`（端口分配）、`status`（上次刷新快照，重启后 UI 可见）、`health`（健康/封禁状态）。
- 启动序列（`startSubscriptionManager`）：`startSavedBoxes` 用文件节点直接起 Box（封禁节点也监听但不进轮询池）→ 3 秒后异步刷新订阅（失败 4 次退避重试）→ 2 分钟后进入探测循环。
- 实测：重启日志 `从文件加载并启动 154 个节点(2 个订阅) → 刷新完成: 154 节点生效`，端口与健康状态全程稳定。

### 3.7 后台「全部检测 / 单独检测」

| 入口 | 行为 |
|---|---|
| 「🩺 检测节点」按钮 | 全量检测：`POST /admin/api/subscriptions/probe`（空 body），同步等待一轮探测完成，返回 `summary` + 最新 `status` |
| 每个节点行「🔍 检测」按钮 | 单独检测：同端点带 `{"localPort":N}`，走 `probeSingleNode`，只探测该节点 |

`probeSingleNode` 语义：

- **封禁节点**：仅探测展示结果，状态不变（给「清除封禁前确认节点是否真通了」用）；
- **成功**：写回健康表（ok / fails=0 / 延迟）→ 刷新 `Status.Nodes` 视图 → `saveSubStore()`；
- **失败**：`fails++` 达阈值 2 → 返回 `status="deleted"` 并触发 `removeDeadNodes`；未达阈值返回 `"failed"`，同样刷新视图 + 持久化。

> **踩坑记录**：失败路径最初只改了 Health 表、没有同步重建 `Status.Nodes` 视图，导致检测后 API 返回旧快照（`lastProbe` 不动）。视图必须与健康表同步更新——两个路径都要 `subscriptionNodeViews()` + `saveSubStore()`。

## 4. 配置项（当前生效值）

| 配置 | 字段 | 当前值 | 范围 | 说明 |
|---|---|---|---|---|
| 订阅自动刷新 | `intervalMin` | **30 分钟** | 30-1440 | 定时拉取订阅并 merge |
| 节点健康检测 | `probeMin` | **5 分钟** | 5-1440 | 定时探测，0 = 默认 15 |
| 失效阈值 | `subDeadThreshold` | 2 次（常量） | — | 连续 2 次失败才删除 |
| 探测超时 / 并发 | `subProbeTimeout/Workers` | 12s / 12（常量） | — | — |

配置修改走后台「💾 保存并刷新」（`POST /admin/api/subscriptions/update`），保存即持久化并自动触发一次刷新。

## 5. 后台 API 一览（[admin.go](../internal/app/admin.go) L119-123）

| 端点 | 方法 | 作用 |
|---|---|---|
| `/admin/api/subscriptions` | GET | 状态总览（节点视图/active/banned/probing 等） |
| `/admin/api/subscriptions/update` | POST | 保存配置（enabled/urls/intervalMin/probeMin）并异步刷新 |
| `/admin/api/subscriptions/refresh` | POST | 立即刷新订阅（同步等待完成） |
| `/admin/api/subscriptions/probe` | POST | 健康检测：空 body=全量，`{"localPort":N}`=单独 |
| `/admin/api/subscriptions/unban` | POST | 清除全部封禁标记 |
